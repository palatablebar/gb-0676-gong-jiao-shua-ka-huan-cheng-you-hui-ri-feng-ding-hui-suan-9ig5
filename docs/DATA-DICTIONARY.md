# 数据定义

刷卡事件以event_id去重，card保留前导零。route支持1路/01等别名。event_time必须带偏移；业务日为Asia/Shanghai。result仅success可作为行程，失败刷卡隔离。reported为实扣人民币元。票价F1至2026-11-01前为2元，F2为2.50元。

跨线路换乘必须在上一次实际付费行程后60分钟内，恰好60分钟排除。同线路无优惠；零付费行程不能延长换乘锚点。先扣1元换乘优惠，再对卡号业务日施加6元封顶。每条基本票价=实算扣费+换乘优惠+封顶优惠+接驳免扣。

车辆故障时，乘客在note携带`故障单:编号`于接驳车补刷。故障单登记经`parameters.fault_orders`传入（缺省用内置演示登记F001），每项含id、route（故障线路）、shuttle_route（接驳线路）、start、end（半开时段）。补刷同时满足四项核验才认定并入续程：故障单已登记且信息完整；该卡在故障时段内于故障线路有原始成功刷卡；补刷线路等于登记接驳线路；补刷时间在故障时段内。并入续程的补刷继承原车次连续关系：沿用原行程编号、应扣为0、接驳免扣等于基本票价、不成为换乘锚点、不消耗日封顶，后续行程换乘窗仍锚定原付费车次。故障单未登记、信息不全或找不到原车次刷卡的记未核清，暂按普通行程收费且批次不得封存日结；故障单已知、原车次已找到但补刷线路或时段不符的记仍需收费，按普通行程收费且不阻塞封存。同一（卡号,故障单）的补刷只认定一次，重试记录隔离为SHUTTLE_RETRY，不重复免扣。优惠回算、清分对账与日结归档引用行程配对产出的同一认定字段；原始刷卡、故障凭证号与重试记录全部保留在结果行或隔离账中并进入证据导出。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。
